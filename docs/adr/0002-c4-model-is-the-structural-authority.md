# ADR 0002: Diagrams first: the C4 model is the structural authority

## Context and Problem Statement

Architecture diagrams drift from code because nothing checks them, and code written quickly by AI agents drifts
from intended structure faster than people notice. Existing open-source Java tools check one direction: ArchUnit's
PlantUML rules and Spring Modulith fail on dependencies the model does not allow, but not on dependencies the model
requires and the code lacks. Where does the intended structure live, and what keeps code and model consistent?

## Decision Drivers

- One source for people (rendered views) and machines (checks, agent context).
- Both directions: an undeclared dependency and a missing required dependency must each fail the build.
- Evidence a reviewer can read: class, member and source line for every reported edge.
- The model must not be weakened silently to make a failing build pass.

## Considered Options

1. Structurizr DSL workspace as authority, checked by the in-repository library `c4-contract-kit`.
2. The code as the model: Spring Modulith's derived module graph only.
3. ArchUnit PlantUML component diagrams (`adhereToPlantUmlDiagram`).
4. LikeC4 or Mermaid C4 as the model format.

## Decision Outcome

Chosen option 1.

- `architecture/workspace.dsl` holds the C4 model: system context, containers, and the seven modules of the API as
  components. Its header comment defines the contract properties: `contract.root` and `contract.isolated` on the
  API container; `contract.id`, `contract.packages` and `contract.status` (`built` or `planned`) on components;
  `contract.mode` (`REQUIRED` or `PERMITTED`, default `PERMITTED`) on component relationships.
- `c4-contract-kit` parses the file with Structurizr DSL 6.2.4 in a restricted mode (no includes, scripts, plugins,
  docs, ADR imports or environment substitution; implied relationships disabled), maps compiled classes to components
  by package, and compares direct static dependencies with the declared edges. Results use reflexion-model terms:
  convergence, divergence (fails), absence of a REQUIRED edge (fails), no static evidence for a PERMITTED edge
  (reported), not evaluated (planned component).
- Model first: a change that adds, removes or redirects a module dependency changes `workspace.dsl` in the same pull
  request, and the reviewer reads the model change before the code.
- Rendered C4 views, the dependency matrix and module pages are generated by the repository's own docs tool from
  `architecture/workspace.dsl` and the verified module structure, not by Spring Modulith. Structural diagrams are
  never drawn by hand. Mermaid is used only for sequences, state machines and the README process overview.
- The library's own internal structure is governed by its self-model `libs/c4-contract-kit/architecture/self.dsl`
  (library slice 4); `architecture/workspace.dsl` is the authority for the product.

### Consequences

- Good, because the model in the review is the model that the build checks.
- Good, because REQUIRED edges turn intended collaborations (for example audit listening to shipment events) into
  failing builds when someone deletes them.
- Bad, because every structural change needs the owner's approval, which slows refactoring across modules.
- Bad, because the check sees static references only. A REQUIRED edge proves a reference exists, not that the
  behaviour runs; reflection, configuration and SQL are invisible to it (docs/gaps.md).
- Neutral, because planned modules are in the model with no code; they become checked when their status changes to
  `built`.

### Confirmation

- `java` runs `ArchitectureConformanceTest` in `:apps:shipping-api`. It calls
  `Conformance.check(architecture/workspace.dsl, <main class output directories>)` and writes
  `build/reports/c4-contract/report.json` and `report.md` before failing.
- Model validation (overlapping, empty or uncovered mappings; planned components with code; tag and property
  disagreements; cycles; forbidden directives) is part of the same call and covered by the library's tests
  (`RestrictedDslParserTest`, `MappingValidationTest`).
- `docs-brain` regenerates views and model pages and fails on any diff.
- `risk-approval` classifies `architecture/**` as level 3; `.github/CODEOWNERS` assigns it to the owner.
