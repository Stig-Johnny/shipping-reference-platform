# Review: Mermaid 11.17.2, vendored browser bundle `dist/mermaid.min.js`

**Method.** Read on 2026-11-06 through WebFetch (GET only, 10 MB cap; shell network and local hashing not permitted):
npm registry metadata and attestations, the unpkg listing, GitHub source and `pnpm-lock.yaml` at tag `mermaid@11.17.2`,
OSV, deps.dev, Scorecard. Nothing was downloaded, unpacked or run; the tarball exceeds 10 MB. `TAG/` =
`https://raw.githubusercontent.com/mermaid-js/mermaid/mermaid@11.17.2/`.

## 1. Verdict
**APPROVE-WITH-CONDITIONS.** Release provenance is strong (trusted publisher on GitHub Actions, SLSA v1 provenance,
verified by deps.dev), and no mermaid advisory covers 11.17.2. But the bundle embeds **DOMPurify 3.4.12 (five open
advisories), lodash-es 4.17.23 (two) and KaTeX 0.16.47 (one)**, fixed upstream only in the 12.x line. Each needs a
non-default configuration, an uncalled function or attacker-controlled diagram text. None is reachable while we render
only our own generated, validated definitions in `strict` mode under a restrictive CSP. Without those conditions this
would be a REJECT.

## 2. What it is and why it is needed
It renders the generated `SystemContext`, `Containers`, `ApiComponents` and `QuoteBookLabel` flowcharts to inline SVG
on the public site. The file is vendored, verified by SHA-256 and served locally, with no CDN, npm install or
browser-based build step, under `securityLevel: "strict"` and `htmlLabels: false` (`docs-site-design.md` §2).

## 7. Execution privileges (visitor's browser, page runtime)
- **What it can do.** As a same-origin script it has the page's full rights: read and rewrite the DOM, send requests to
  any origin, use storage for the Pages origin (shared with the owner's other project sites; the site holds no
  credentials or sessions). A poisoned bundle could falsify page content or exfiltrate what the visitor sees. The CSP
  in condition 6 blocks the network paths (`connect-src`, `img-src`, `worker-src`), and condition 7 keeps the bundle
  off the Trust pages.
- **What it does under our configuration.** It parses the definition text and writes SVG with inline styles into the
  DOM. Under strict, label HTML is sanitised, click callbacks are off (`setClickFun` runs only in `loose`), links pass
  `@braintree/sanitize-url`, and the final SVG goes through DOMPurify.
- **No network by default:** no fetch in `mermaid.ts` or `icons.ts`; icons come only from packs the page registers.
  **Exception:** image nodes (`@{ img: … }`) load their URL even under strict (`imageSquare.ts`); hence condition 4.
  KaTeX is loaded with `import('katex')`, which `splitting = false` should inline (not verified).
- **No build-time execution:** it never runs in CI or on build hosts.

## 8. Direct dependencies as published
The 22 `dependencies` in [package.json](https://unpkg.com/mermaid@11.17.2/package.json) are all compiled into the file
(resolved versions in §6). There are no install scripts, and the tarball is never installed, so none of them runs
outside the browser. Flagged: DOMPurify, lodash-es and KaTeX (advisories) and khroma (licence unrecorded).

## 9. Alternatives considered
Mermaid 12.3.0 fixes the DOMPurify and lodash-es advisories but needs ES2024/Safari 17.4+ and its own review.
Rendering to static SVG at build time needs a headless browser in CI, a larger review. Structurizr-exported images
would not match GitHub's rendering.

## 10. Conditions and residual risk
**Conditions:** see the frontmatter. **Residual risk:** (1) a pinned file on a line that gets no fixes, so a future
DOMPurify bypass of the default string path stays open until the move to 12.x; (2) inline styles need
`style-src 'unsafe-inline'`; (3) the github.io origin is shared.
