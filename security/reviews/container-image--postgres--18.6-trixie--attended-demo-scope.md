# Scope extension: PostgreSQL 18.6-trixie as the attended demo database

**Not a new review.** This record extends `container-image--postgres--18.6-trixie.md` ("the base record"), which
approves this image by its index digest as a throwaway database for the Testcontainers tests, in CI and in the colima
profiles `rigbuild` and `demotest`. Its provenance, licence and execution findings stand.

What is new is one more use of the same digest: the database behind the API's `demo` profile on the owner's MacBook,
for one attended session. Every base condition still applies; this record adds lifetime, operator and data
conditions:

- **Digest only.** The base conditions 1 and 2.
- **No init scripts, copies or mounts.** Base condition 3; this record adds "no named volume".
- **A random password and loopback only.** Base condition 4; this record adds the password's handling.
- **Removal with the volume.** Base condition 5.
- **Re-review on a new digest, 18.7 or a CVE.** Base condition 6.
- **A reviewed engine.** Base condition 7.

## 1. Verdict

**APPROVE-WITH-CONDITIONS**, for an attended demo database with synthetic data that lives for one session. The image
and its risks are those of the base record. A demo needs no other image, no initialisation script and no persistent
data. The conditions keep it that way, and the engine record keeps the whole use blocked until the MacBook matches the
reviewed versions.

## 2. What it is and why it is needed

The plan requires the API's `demo` profile to use PostgreSQL: Flyway migrations, transaction-local tenant binding,
row-level security and separate migration and runtime roles. An in-memory store would not show a database-backed
demo. The owner runs the same revision that CI tests, so the image is the one CI uses, by the same digest.

## 6. License

## 7. Execution privileges

- **Unchanged inside the engine:** the entrypoint runs as root, then `gosu postgres`. It listens on 5432 in the
  container.
- **What changes for the demo.**
  - The API connects from the host over the loopback-published port, with the session's random password.
  - The container lives for the session, not for one test run.
  - Its data is synthetic and is deleted with the anonymous volume at the end.

## 8. Direct dependencies as published

Unchanged: `debian:trixie-slim`, the PGDG `postgresql-18` packages and gosu 1.19, covered as part of this digest.

## 9. Alternatives considered

- **An in-memory store.** It would not be the database-backed demo the plan requires.
- **A persistent named volume.** It would keep demo data between sessions, which the demo does not need.
- **A different tag or a newer digest.** A new review.

## 10. Conditions and residual risk

**Conditions:** see the frontmatter.

**Residual risk.**

- **A shared loopback port.** For the session, every process of the owner's user can reach it, with the password
  needed to log in.
- **Unscanned packages.** The image's Debian packages and gosu were not scanned (base record).
